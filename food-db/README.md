# 식약처 식품영양성분 DB 연결

탄수화물 계산기(`/index.html`)의 음식 검색은 식약처 데이터를 두 가지 방법으로 씁니다.

| 종류 | 어디서 | 속도 |
|---|---|---|
| 조리 음식·원재료 (갈비탕, 고구마 등 7천여 가지) | `foods.tsv` — 사이트에 같이 올라가는 파일 | 즉시 |
| 가공식품 (제품) | 아래 Apps Script 서버 → 공공데이터포털 API | 몇 초 |

## 음식·원재료 파일 (`foods.tsv`) 다시 만들기

1. 공공데이터포털에서 **통합식품영양성분정보(음식)**, **(원재료성식품)** CSV를 새로 받습니다.
2. `raw/` 폴더의 같은 이름 파일을 바꿔 넣습니다.
3. `python3 food-db/build-foods.py` 를 실행하면 `foods.tsv` 가 다시 만들어집니다.
   - 탄수화물 값이 없는 항목(주로 프랜차이즈 메뉴)은 뺍니다.
   - 이름·업체가 같은 항목은 열량이 중간인 것 하나로 합칩니다.

## 가공식품 검색 서버 (Apps Script)

가공식품은 수십만 개라 파일로 넣기엔 너무 커서, 아래 서버가 공공데이터포털 API를 대신 불러 줍니다.
구글 Apps Script에서 돌아가고 무료입니다.

```
사이트(index.html) ──?q=짜장면──▶ Apps Script(Code.gs) ──API 키──▶ 공공데이터포털(식약처)
```

- API 키는 Apps Script 안에만 저장되고 사이트 코드에는 드러나지 않습니다.
- 같은 검색어는 6시간 동안 저장해 두었다가 다시 쓰기 때문에 하루 호출 한도를 아낍니다.
- 설정 전(`FOOD_DB_URL`이 비어 있을 때)에는 기존처럼 기본 목록 + Open Food Facts만 검색합니다.

## 설정 (10분, 한 번만)

### 1. API 키 받기
1. https://www.data.go.kr 로그인 → **"식품의약품안전처_식품영양성분DB정보"** 검색
2. **활용신청** → 목적 아무거나(예: 개인 영양 계산기) → 신청. 보통 바로 승인됩니다.
3. **마이페이지 → 데이터 활용 → Open API → 활용신청 현황**에서 그 API를 누르면 **일반 인증키(Decoding)** 가 보입니다. 복사해 둡니다.
   - 승인 직후 1시간쯤은 키가 "등록되지 않은 키"로 나올 수 있습니다. 잠시 뒤 다시 해 보세요.

### 2. Apps Script 만들기
1. https://script.google.com → **새 프로젝트** → 이름을 `식약처 음식 검색`으로
2. 원래 있던 `Code.gs` 내용을 모두 지우고, 이 폴더의 **`Code.gs`** 를 통째로 붙여 넣고 저장(💾)
3. 왼쪽 **⚙️ 프로젝트 설정 → 스크립트 속성 → 스크립트 속성 추가**
   - 속성: `MFDS_API_KEY`
   - 값: 1번에서 복사한 인증키
4. 편집기로 돌아와 함수 선택 칸에서 **`testSearch`** → **실행**
   - 처음엔 "권한 검토" 창이 뜹니다 → 내 계정 → "고급" → "(안전하지 않음)으로 이동" → 허용 (본인이 만든 스크립트라 뜨는 안내)
   - 실행 로그에 `결과 N개`와 짜장면 영양 정보가 나오면 성공입니다.

### 3. 웹 앱으로 배포
1. 오른쪽 위 **배포 → 새 배포** → 톱니바퀴에서 **웹 앱**
   - 실행 계정: **나**
   - 액세스 권한이 있는 사용자: **모든 사용자**
2. **배포** → 나온 **웹 앱 URL** (`https://script.google.com/macros/s/…/exec`)을 복사
3. 저장소 루트의 `index.html`에서 아래 줄에 붙여 넣고 커밋합니다 (또는 Claude에게 주소를 알려 주세요).
   ```js
   const FOOD_DB_URL = 'https://script.google.com/macros/s/…/exec';
   ```

브라우저에서 `웹앱URL?q=바나나` 를 열어 `{"ok":true,"items":[…]}` 가 보이면 잘 된 것입니다.

## 문제가 생기면

| 증상 | 확인할 것 |
|---|---|
| `"error":"api"` + `SERVICE_KEY_IS_NOT_REGISTERED` | 키가 아직 활성화 전(1시간 대기)이거나, 다른 API의 키를 넣었음 |
| `스크립트 속성 MFDS_API_KEY 가 비어 있어요` | 2-3 단계의 속성 이름 철자 확인 |
| `"error":"busy"` | 하루 호출 한도 초과 → 다음 날 풀림. 공공데이터포털에서 운영계정 신청 시 늘어남 |
| 결과는 나오는데 탄수화물이 이상함 | 편집기에서 `testRaw` 실행 → 로그의 필드 이름을 `Code.gs`의 `normalize_` 와 비교 |
| `Code.gs` 를 고쳤는데 그대로 | **배포 → 배포 관리 → ✏️ → 버전: 새 버전 → 배포** 해야 반영됩니다 (주소는 그대로) |

## 값의 기준

- 식약처 DB는 보통 **100g당** 값을 줍니다. 서버가 기준량(`SERVING_SIZE`)을 보고 100g당으로 바꿔서 보냅니다.
- 식품 중량(`Z10500`)이 있으면 그 양을 "1회" 기본 섭취량으로 담고, 없으면 100g으로 담습니다.
